# Contributing to Wellfarm

## Before starting

1. Read the product requirements and the relevant module README.
2. Open or assign a focused issue with a testable outcome.
3. Confirm that any dataset, model, map, or content source has a compatible license.
4. Never add credentials, private farmer data, or unapproved treatment guidance.

## Suggested workstreams

- Farmer experience and localization
- Officials' dashboard and accessible mapping
- API and shared contracts
- Vision model and dataset evaluation
- Weather/outbreak analysis and simulated fixtures
- Testing, documentation, and demo preparation

## Changes

- Keep commits small and describe the reason for each change.
- Update contracts and documentation when behavior changes.
- Label simulated data in the record and the interface.
- Add tests once runnable code exists.
- Request review from the owner of the affected workstream.

## Definition of done

A change is understandable, contains no sensitive material, respects the Round 1 scope boundary, and has been checked at the level appropriate to its risk. User-facing changes include accessible states for errors, uncertainty, and simulation labels.
